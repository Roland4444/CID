# Контроль ИД — Rust + Axum + Synology File Station HTTPS + PostgreSQL (v0.5)

**Статус:** исходники пилотного приложения. Предыдущий v0.4 использовал SMB-монтирование; этот проект **напрямую подключается к DSM по HTTPS:5001**. Используется только File Station API: `SYNO.API.Auth`, `SYNO.FileStation.List`, `SYNO.FileStation.Download`. Оригиналы NAS не изменяются. PostgreSQL находится локально на Ubuntu (`127.0.0.1:5432`).

Полная пошаговая установка: **[INSTALL_UBUNTU_RU.md](INSTALL_UBUNTU_RU.md)**. Краткая инструкция: **[QUICKSTART_RU.md](QUICKSTART_RU.md)**.

## Что делает

- Фоновое рекурсивное сканирование **одной настроенной** папки `SYNOLOGY_ROOT` через HTTPS 5001. Постраничный обход, проверка `mtime` и размера, скачивание только новых/изменённых файлов, контроль размера и SHA-256.
- Структура `Объект/Вид работ/ИД/файл` и `Объект/Вид работ/ПД-РД/файл`; автосоздание внутренних проектов/комплектов в PostgreSQL. **Интеграции с Bitrix24 пока нет.**
- Неизменяемые локальные архивы оригиналов, история версий, аудит, файлы PDF/DOCX/XLSX/JPG/PNG, OCR.
- Каталог из 14 видов работ, 169 позиций исполнительной документации и 34 типовых ошибок, взятых из исходного ТЗ.
- Проверки комплектности по выбранному инженером чек-листу и базовый движок утверждаемых ГОСТ/СП/приказов: обязательная/недопустимая фраза, регулярное выражение, ручная проверка. Правила без утверждения не применяются.
- Подтверждение замечаний инженером и выгрузка реестра XLSX/DOCX/PDF.
- Орфографическая коррекция не включена.

**Ограничения:** проверка текста и реквизитов не равна полноценной экспертизе нормативного соответствия. Не реализованы полная проверка чертежей, допусков, журналов и полноценные роли из ТЗ. Нет гарантии работоспособности до реальной компиляции и испытаний на DSM. Из-за отсутствия `cargo`/`rustc` в среде генерации компиляция не была подтверждена.

## Конфигурация

```dotenv
DATABASE_URL=postgresql://idcontrol:DB_PASSWORD@127.0.0.1:5432/idcontrol
LISTEN=127.0.0.1:8090
SYNOLOGY_URL=https://nas.example.local:5001
SYNOLOGY_USERNAME=id_reader
SYNOLOGY_PASSWORD=NAS_PASSWORD
SYNOLOGY_ROOT=/resdata/Исполнительная документация
SYNOLOGY_VERIFY_TLS=true
# SYNOLOGY_CA_CERT=/etc/id-control-axum/synology-ca.pem
DATA_ROOT=/var/lib/id-control
POLL_INTERVAL=45
STABLE_SECONDS=15
MAX_FILE_MB=100
OCR_MAX_PAGES=20
APP_USER=admin
APP_PASSWORD=A_DISTINCT_16_CHAR_OR_LONGER_SECRET
```

Это путь **File Station**, который начинается с имени общей папки `/resdata`, а не `/volume1/resdata`. TLS-верификация включена по умолчанию. Специальное отключение `SYNOLOGY_VERIFY_TLS=false` — только временная диагностическая мера, не рекомендуемая в эксплуатации.

## Быстрый старт

```bash
cp .env.example .env
nano .env
cargo check
cargo test
cargo build --release
./target/release/id-control-axum --check-synology
./target/release/id-control-axum
```

Подробное создание PostgreSQL, установка OCR, `systemd`, Nginx, права на файлы и диагностика: `INSTALL_UBUNTU_RU.md`. Перед запуском PostgreSQL должен существовать, а пользователь БД должен иметь право `CREATE` (миграции `001`–`004` выполняются при старте).

## Интерфейс

- `/` — проекты и комплекты;
- `/packages/{id}` — документы, проверки, замечания, версии;
- `/norms` — реестр утверждаемых нормативных правил;
- `/catalog/errors` — типовые ошибки;
- `/packages/{id}/report/xlsx|docx|pdf` — отчёты;
- `/health` — последняя успешная проверка связи и число утверждённых норм.

Нормативные документы не включены в проект; специалист должен подтвердить редакции/пункты ГОСТ/СП на основе оригиналов. Настройка в `docs/NORMS_SETUP_RU.md`.

## Технические свойства

`SynologyClient` реализован через `reqwest` и `rustls` (`src/synology.rs`), `scanner.rs` повторно использует существующий локальный конвейер извлечения документа после загрузки в временный каталог. Скрипт `004_synology_index.sql` добавляет индекс метаданных NAS. Расход сетевого трафика ограничивается сравнением размера+времени изменения; совпадение метаданных не гарантирует обнаружение редких правок, если файл был изменён с сохранением и размера, и `mtime`. Для окончательной проверки используются SHA-256 скачанных файлов.

Результаты сканирования сохраняются в локальной PostgreSQL, NAS используется только для чтения. В случае ошибки удалённого обхода документы не объявляются удалёнными. При пустом дереве автоматическая массовая пометка отсутствующих документов блокируется.
